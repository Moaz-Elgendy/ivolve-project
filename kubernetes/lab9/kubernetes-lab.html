Inspect the Node object

The default taint is:

node-role.kubernetes.io/control-planeNoSchedule

Toleration ≠ placement

A matching toleration permits consideration of the control plane. It does not force the scheduler to choose it.

Static control-plane pods and tolerant system DaemonSets still run there. NoSchedule does not evict existing pods.

What the test proves

A pod on the worker proves placement only when supported by real output. Two pods on the same worker do not demonstrate cross-node VXLAN.

Flannel's configured network must match kubeadm's pod CIDR. The overlay requires working node-to-node reachability underneath.
